# OM AI security, accuracy and privacy

1. **Keep it private.** The existing GitHub Pages operations dashboard is public; never publish raw payroll, bank statements, incidents, customer details or live APIs there. OM AI should run as a **separate** Google Apps Script web app.
2. **Google identity + allowlist.** Every business data call verifies `Session.getActiveUser().getEmail()` against the private `Users` sheet. A missing email fails closed. Admin/Manager/Viewer roles and store IDs are enforced server-side.
3. **No true per-store confidentiality within one shared Sheet.** Server-side role/store filtering applies to UI/API calls, but anyone with underlying Sheet read permission can inspect every tab and store record in that file. Use only trusted staff who may access all included stores. For real per-store secrecy, use separate per-store databases and verified identity on an owner-executed backend. `setupOmAi()` attempts to protect `Users`, `Stores`, and `AuditLog` tabs against other Sheet editors, but this is not a substitute for file-level confidentiality.
4. **Run as accessing user, not owner.** `USER_ACCESSING` plus Google Sheet sharing ensures that an authorized user has an explicit Google permission to access the database. If you change deployment mode, you must redesign/retest authentication.
5. **No secrets in front end.** Set `OWNER_EMAIL`, `TOMTOM_API_KEY`, `GEMINI_API_KEY`, `GEMINI_MODEL` and optional `DIGEST_EMAIL` in Apps Script Script Properties. Never paste them into GitHub, Sheet cells or HTML templates.
6. **Data minimization.** The AI prompt includes store KPIs, source types and alert titles, not raw receipts, staff IDs, video, detailed incident descriptions or personal customer information. News is untrusted and the assistant is instructed not to follow embedded commands.
7. **Provider limitations.** NWS is a forecast/alert feed, TomTom is nearby road speed/incident information, and Google News RSS returns mentions. They are not official proof that a road is safe/open or that store sales will change.
8. **Human verification.** Financial and regulatory impacts, road projects, tax and permit deadlines, and model recommendations require review against original sources.
9. **Spreadsheet formula injection.** Human-entered text that begins with a formula operator is escaped. Server-side enum/date/numeric validations exist, and all write APIs enforce user/store permissions.
10. **Operational safety.** Do not use this tool for emergency routing, dispatch, or severe weather life-safety decisions. Refer to FL511, NWS, local emergency management and other official providers directly.
11. **Before larger deployment:** add data backups, granular editor protection, data retention, monitoring/incident response, provider quota management and an independent security review. As delivered, this is a functional MVP, not an audited production security system.
